This is a walkthrough of actual product screens, not a simulated payout. Record the real application and the genuine public NEAR testnet receipts. Do not claim authentic extension signing was proven.

| Time | Screen | What the audience sees |
| --- | --- | --- |
| 0–12s | Preserve the cinematic homepage; choose **Open App**. | A real funding product rather than a developer console. |
| 12–28s | Workspace overview and Campaigns. | Real, recorded testnet campaigns and the dependency relationship between Alpha and Beta. |
| 28–45s | Open the two-project campaign. | Immutable funding rules and the live finalized status if testnet RPC responds; otherwise an explicit unavailable state. |

| 65–80s | Open expired campaign and refund receipts. | A contribution was refunded when funding did not activate. |
| 80–100s | Create campaign (blank draft). | User creates project goals, dependencies and supporter constraints with no seeded fictional data. |
| 100–115s | Verify a recorded transaction. | Real read-only verification tied to the pinned contract code hash, if the RPC is reachable. |

Do not demonstrate wallet signing as successful without a genuine browser receipt. Clearly state that this is testnet-only and that a missing withdrawal callback blocks valuable-money production use. Do not record false green verification during RPC outages.
